# everything.dev

The open runtime for apps on NEAR — composed from published config and loaded through a shared host, UI, and API runtime.

## Language

**Runtime**:
A published app configuration (`bos.app.ts` authored, resolved through `extends`) that the host loads as remotes.
_Avoid_: app (ambiguous between the runtime and a tenant), project

**SlotResolver**:
The host's entry-URL seam (`entryUrls` in `everything-dev/ui/slot`) — one pure derivation from a stamped config slot (`EntrySlot`) to the URLs each surface loads: `web` (browser entry — bustered fixed name in development, pin-derived hashed outside it), `ssr` (server container entry; undefined when the slot has no SSR coordinates), and `browserManifest` (the pin-derived hashed mf-manifest, structurally absent for local slots — atomic-deploys 08). Surfaces resolve lazily and throw loudly outside development naming slot + surface; buster arithmetic (integrity for web, ssrIntegrity→containerVersion for the server) lives inside the module, never at call sites.
_Avoid_: resolveEntryUrlForEnv (the deleted per-surface helper), remoteEntryUrlOf/ssrEntryUrlOf/getSsrEntryUrl (the deleted per-site wrappers), buster at the call site

**Quiet build**:
The prerequisite dist builder in `everything-dev/build` — one function (`buildPackageQuietly`) over the three framework packages (every-plugin, better-near-auth, everything-dev), each identified by its staleness-check dist entry. Skips when the dist is fresh, rebuilds captured-output-quietly, and fails loudly on nonzero exit; used by `bos build`'s train and the `bos dev` boot build.
_Avoid_: buildEverythingDevQuietly/buildEveryPluginQuietly/buildBetterNearAuthQuietly (the deleted triplication), force-rebuild as the default path

**Authored surface**:
The ui files an app owns and edits freely — routes, lib, components, plus the scaffolded-once `router.tsx` (router policy) and `app.ts` (`@/app` public surface). The framework owns none of it after init.
_Avoid_: framework files (ambiguous — the generated stubs are framework-owned too), boilerplate

**Framework-owned file**:
A child-repo file in the `src/services/scaffold/ownership.ts` inventory (everything-dev package) — reconciled from the parent template by `bos sync` / `bos upgrade` with three-way hash comparison, template-wins-on-conflict, and backups under `.bos/sync-backup/` (ADR 0032). Local edits are legitimate; a permanent change requires an upstream issue at the framework repo, which ships it in package versions.
_Avoid_: sync file (implementation detail), boilerplate (ambiguous), "don't touch" framing (the marker says edits are allowed)

**Upstream-change protocol**:
The standard for changing framework behavior (ADR 0032): edit framework-owned files locally when needed, then file an issue at https://github.com/NEARBuilders/everything-dev/issues describing the change — the framework team implements it in the parent repo via PR + changeset and ships it in package versions, after which the child copy and the template converge. A local edit without an upstream issue is an undocumented fork claim.
_Avoid_: "you can't change this" (wrong), silent forking (the issue is the contract)

**Generated stub**:
A `.gen`-suffixed, gitignored ui file the framework emits — web entry, hydrate wiring, SSR router module, compose expose, globals — regenerated by dev/build/typecheck from the installed package version, never edited or synced.
_Avoid_: sync file, template file (sync no longer carries ui source)

**Deploy leg**:
One of the post-publish stages of `bos deploy` — `image` (build/push or pin the runtime image), `smoke` (the boot gate), `railway` (the redeploy trigger). Each leg reports an outcome (ok / skipped / failed + reason) on the deploy result; a skipped leg never fails the deploy.
_Avoid_: stage (dev/build/upload/publish are train stages, not legs), step

**Runtime tier**:
Whether the deploy train owns its runtime image — `root` (`ci.image` configured or a Dockerfile at the config root; the train can produce a digest and must pin Railway to it) or `child` (inherits the platform's universal image per ADR 0020/0021; no image bytes to build, pin, or boot). One function resolves it; the image, smoke, and Railway gates all consume it.
_Avoid_: root vs consumer (the account naming, not the image-ownership question), tenant tier

**Platform release manifest**:
The machine-readable contract of one framework release (ADR 0034): framework + every-plugin versions, the release catalog, exact shared-dep versions with their flags, the hashed template inventory, and the compat floor — composed once by the deploy train and published to two homes with byte-identical content (the FastKV pointer slot `apps/<root-account>/<root-gateway>/platform.json` beside the config, and the in-image copy generated inside the docker build). Carries image `ref` + tags, never the digest.
_Avoid_: version manifest (that's the per-workspace deploy pin), plugin manifest (the per-plugin bundle metadata), release notes

**Derived pin**:
The child's single authored `platform: "<framework-version>"` field in `bos.app.ts` — everything else (catalog entries, `ci.image` as `ref@digest`, the release-scoped sync source, compat verification) derives from the resolved manifest, so no hand-correlated pin pairs remain. Exact in v1: no ranges; absent means latest via extends.
_Avoid_: platform version (ambiguous with the manifest's own `frameworkVersion`), image pin (the digest is derived, not authored), version bump

## Organization access

**Team**:
A named sub-group within an organization that shares access to the organization's feature areas.
_Avoid_: team account, team wallet

**Active Team**:
The Team currently selected for a user's organization work.
_Avoid_: current team, team account

**Feature Area**:
A product capability that an organization can grant to a Team.
_Avoid_: permission, role

**Team Workspace**:
The organization view scoped to an Active Team and its granted feature areas.
_Avoid_: organization account

**Statement**:
A declared resource-to-actions entry in the permission catalog (`email: ["read"]`); the only things a role can grant. Undeclared means denied.
_Avoid_: permission (reserve for a statement:action pair), scope, binding

**Role Grant**:
The per-statement action grants a Role carries, declared in the runtime's `siwn.permissions.roles` config — the plugin ships no defaults.
_Avoid_: role permissions, role config

**Effective Permissions**:
The caller's resolved statement-to-actions map as of the request: session principals get their active organization's role grants, API-key principals get the key's declared permissions, anonymous callers get none. Surfaced by `getContext` and checked by `requirePermission`.
_Avoid_: permissions (unqualified, when you mean the resolved map), grants (when you mean the map)

**Permission Registry**:
The runtime's normalized statements catalog plus role grants, built from config at boot and exposed as the auth plugin's registry service.
_Avoid_: ACL, access list

**Session Data Cookie**:
Better Auth's short-lived cookie cache of the session as of its last refresh; its team guards resolve the session from it, not from the database row. Writes that clear session state in the database strip it from the forwarded request so the guard re-reads the fresh row via the session token.
_Avoid_: session cache, active-team cookie (say which state it caches)

**Gateway Origin**:
The canonical base runtime origin for a network, where every passkey ceremony takes place regardless of which domain the member arrived from.
_Avoid_: base URL, main domain

**Device Link**:
Signing a desktop browser into an existing session by approving the desktop's QR code from a phone that is already signed in.
_Avoid_: device pairing, sync, cross-device passkey (the browser-native hybrid flow is a different mechanism)

## Regression stacks

**Stack**:
The fixture a regression suite runs against: `start` (the production command — the host booted over locally built, statically served artifacts via `bos start --config`) or `dev` (the dev server, `bos dev` — smoke-covered only).
_Avoid_: environment (that's `production`/`staging`), target

**Variant**:
The render mode a stack runs with: `ssr` (server-composed) or `csr` (no ssr URL — the client composes). Written `stack:variant` (e.g. `start:csr`); a bare stack name runs both variants serially (`test:regression:start` / `test:regression:dev`).
_Avoid_: mode (reserved for `production`/`staging` env), project

**Stall Watchdog**:
The Playwright reporter that fails the suite after minutes of zero test progress, printing a runner snapshot so a freeze produces evidence instead of eating the job timeout.
_Avoid_: timeout (the job-level kill; the watchdog exists because that kill loses artifacts)

## Gasless transactions

**Gas Key**:
A NEAR access key (NEP-611) with its own prepaid gas balance and parallel nonce lanes; gas burns from the key's balance, not the account's.
_Avoid_: prepaid key, allowance (a function-call key's allowance spends the account's own NEAR — a different mechanism)

**Session Gas Key**:
The browser-generated Gas Key scoped to the FastKV namespace's `__fastdata_kv` method, bootstrapped onto a user's account at their opt-in and used to sign platform writes locally.
_Avoid_: session key, FCAK, gas key (that's the protocol concept — be specific about which)

**Sponsor**:
The funding role of the ephemeral relayer account: it tops up Session Gas Keys via `TransferToGasKey` under server-enforced per-user caps.
_Avoid_: relayer for this role (the relayer is the NEP-366 role of the same account — say which you mean)

**Bootstrap**:
The one-time, wallet-signed `AddKey` transaction that installs a Session Gas Key on the user's account; refused for wallets whose manifest lacks `features.gasKeys`.
_Avoid_: provision, register

**Lane**:
One of a Gas Key's independent nonce sequences; parallel sends pick different Lanes and never serialize on each other.
_Avoid_: nonce (the per-lane counter), slot

## Custody publish

**Custody Wallet**:
An OutLayer Agent Custody wallet (`wk_…` key, TEE-held keys) registered once per user and network during `bos login --custody`; its implicit hex account is the signing identity for `publish.auth = "custody"` publishes.
_Avoid_: outlayer credential, agent wallet (say custody)

**Machine identity**:
The custody wallet's implicit hex account as the deploy target: the authored config's `account` must equal it, so configs publish under `apps/<hex-account>/<gateway>` instead of a named account.
_Avoid_: bot account (not a named account), executor (OutLayer's own term for something else)
