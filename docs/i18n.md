# Internationalization

CityNode supports English (`en`), Spanish (`es`), French (`fr`), and Chinese (`zh`). English is the default and fallback language.

## Architecture

The main UI and auth UI are separate Module Federation bundles. Both use the locale runtime exported by `everything-dev/ui/i18n`, while each bundle owns the messages it renders:

- `ui/src/i18n/catalogs.ts` contains main-app messages.
- `plugins/auth/ui/src/i18n/catalogs.ts` contains login and account messages.
- `ui/src/i18n/runtime.tsx` and `plugins/auth/ui/src/i18n/runtime.tsx` configure the shared runtime for each bundle.

Both bundles use the `citynode_locale` cookie and the same browser-side locale store. A change in one bundle is therefore visible to the other without a route change.

Locale precedence is:

1. The signed-in user's saved `locale` preference.
2. The `citynode_locale` cookie.
3. The first supported language in `navigator.languages`.
4. English.

The cookie keeps a signed-out selection for one year. After sign-in, the language selector in Settings saves the preference to the user record.

## Add or change a message

1. Add the English message and a stable key to the appropriate catalog.
2. Add that key to every translated catalog. TypeScript reports any missing key.
3. Read the translator in a component:

   ```tsx
   const t = useAppTranslation();
   return <h1>{t("landing.title")}</h1>;
   ```

   Auth UI components use `useLoginTranslation()` instead.

4. Pass dynamic values as named placeholders:

   ```tsx
   t("apply.slug.available", { hostname });
   ```

Keep keys tied to meaning rather than the current English sentence. Reuse a key only when every locale should use the same wording in both places.

## Add a locale

1. Add the locale code to both `APP_LOCALES` and `LOGIN_LOCALES`.
2. Add its display label to `LOGIN_LOCALE_LABELS`.
3. Add complete catalogs in the main UI and auth UI.
4. Add the catalog to each bundle's translated-message map.
5. Extend the locale resolution, catalog, selector, and browser tests.

Use a base language code unless the product needs region-specific wording. The resolver maps regional browser tags such as `fr-CA` to `fr`.

## Dates, times, and numbers

Use the active locale with the platform formatters instead of fixed patterns:

```tsx
const { locale } = useAppLocale();
const date = new Intl.DateTimeFormat(locale, options).format(value);
const count = new Intl.NumberFormat(locale).format(value);
```

Preserve an event's configured time zone when formatting event times.

## Tests

Run the focused suites after changing translations:

```bash
bunx vitest run tests/ui/i18n.test.ts                  # packages/everything-dev
bunx vitest run src/i18n src/components/discovery/event-list.test.ts  # ui
bunx vitest run ui/src/i18n                            # plugins/auth
```

Also run each touched workspace's typecheck. Browser verification should cover language switching, reload persistence, English fallback, and navigation between auth and main UI routes.
