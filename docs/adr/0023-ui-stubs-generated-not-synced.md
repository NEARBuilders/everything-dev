# ADR 0023: UI bootstrap stubs are generated, not synced

Date: 2026-10-04
Status: Accepted

Depends on: ADR 0005 (app.ts authored descriptor), ADR 0008 (manifest composition), ADR 0022 (two roots).

## Context

The child ui workspace carries eight framework-owned files that `bos sync` whole-file-overwrites from a parent tarball (app.ts, entry.ts, globals.d.ts, hydrate.tsx, router.server.tsx, router.tsx, providers/index.tsx, hooks/index.ts), with three-way hash conflict detection and no line merge. Costs: framework behavior changes ride file copies instead of package versions — two sources of truth for one behavior; the overwrite model demands per-file ownership bookkeeping and gets it wrong (compose.ts claims sync ownership it does not have); apps cannot extend `@/app` without editing a file sync will clobber; and the client router factory in router.tsx is dead code — the framework hydrate mints the router from the composed tree — yet carries the app's only `Register` declaration, so the file both lies and is load-bearing. Meanwhile the repo already runs a generation convention: `**/*.gen.ts` artifacts are gitignored and regenerated by `generateCodeArtifacts` on dev/build/typecheck/publish, and children scaffold `types:gen` into their typecheck. The repo's three MF web exposes `./providers` and `./hooks` (and `./components`) have zero in-repo consumers, and `globals.d.ts` carries two dead ambient module declarations.

## Decision

1. **Authored/generated split by policy vs mechanism.** Everything the app customizes is authored and app-owned; everything mechanical is generated — `.gen`-suffixed, gitignored, emitted by the existing generateCodeArtifacts pipeline. The framework owns zero authored ui source files.
2. **Generated set**: the web MF entry (styles import + deferred bootstrap), the `./Hydrate` bootstrap (wiring the generated routeConfig and the authored router factory into the core hydrator), the SSR router module (node entry + `./Router` expose), the `./compose` re-export, and a globals file trimmed to the rsbuild types reference (the `*.md` and drizzle virtual ambient declarations are dead and deleted).
3. **Authored set, scaffolded once by `bos init`, owned forever after**: `router.tsx` — the real client router factory (`createRouter` + `Register` + optional `createQueryClient`), the single customization seam for notFound/pending/error components, scroll behavior, and query timings; `app.ts` — the `@/app` public surface, ownership flipped from sync-managed to app-owned. Sync stops managing every ui source file.
4. **Invert control.** The core hydrator's interface gains `createRouter`/`createQueryClient`; the framework keeps tree composition, digest parity, and fallbacks; the app owns router policy. This creates a capability that never existed — the framework previously hardcoded the error component and the query client. SSR calls the same authored factory, so server and client render with identical options.
5. **Sync shrinks to config-level ownership** (bos.config.json deep-merge, package.json merge, .gitignore, workflow templates). `bos upgrade` removes previously-synced stub files it detects in children — silently when unmodified, with conflict-plus-backup when hand-modified, matching existing sync semantics. Framework behavior changes flow through package versions from here.

## Consequences

- Web exposes drop `./providers` and `./hooks`; `./components` stays. The every-plugin core-ui detection marker keyed on the old entry path moves with the retarget.
- A fresh clone needs one generation pass before typecheck/build — the same as routeTree.gen today.
- Core routes stay typed via `Register` over routeTree.gen; plugin routes remain runtime-composed and string-typed at `<Link>` until ADR 0008's typed cross-plugin emission lands.
- Sync's snapshot/backup machinery survives for the config files it still owns.
- The old eight-file sync list and its integration tests are replaced by the upgrade-migration contract.
