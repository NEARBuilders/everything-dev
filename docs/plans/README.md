# Implementation Plans

Two kinds of plan live here:

1. **The audit queue** — numbered flat files (001–048) generated by the `/improve` skill on 2026-09-15 (post Effect 4 + oRPC v2 migration survey), amended by later audit sessions. Execute in the order below unless dependencies say otherwise. Each executor: read the plan fully before starting, honor its STOP conditions, and update your row when done.
2. **Architecture docs** — thematic subdirectories: v2 platform design, wayfinder decision maps, runnable prototypes, and sprint ticket sets.

These are architecture and implementation plans, not issue tickets — sprint tickets live in `.scratch/<feature>/issues/` (local, published to GitHub once ready).

## beta-v2 — the v2 platform architecture

The `app.ts` composition model: one TypeScript file declares the entire
application — auth, API, web plugins, native plugins. The host composes
them at runtime via Module Federation. Tenants override by URL. Everything
is verifiable on-chain via FastKV.
