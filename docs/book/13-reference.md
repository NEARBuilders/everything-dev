# 13 · Reference

The lookup tables the rest of the book points back at.

## `bos` commands by task

| Task | Commands |
|---|---|
| Develop | `bos dev` · `bos ps` · `bos kill` · `bos logs` · `bos config` |
| Build | `pnpm run build [target]` — the train; `bos build` for the workspaces alone |
| Scaffold and evolve | `bos init` · `bos import` · `bos sync` · `bos upgrade` |
| Freeze and inspect | `bos lock` (`--check`) · `bos manifest` (`--check`) · `bos status` |
| Publish | `bos login` · `bos secrets set\|list\|remove` · `bos publish` · `bos deploy` · `bos plugin publish` |
| Verify | `bos verify` · `bos mf check` · `bos upgrade --check` |
| Types and data | `bos types gen` · `bos db studio\|doctor\|repair` · `bos seed` |

Flags and options for each are in the
[`everything-dev#cli-reference`](../../packages/everything-dev/skills/cli-reference/SKILL.md)
skill.

## Agent entry points

Every deployed runtime serves these, and every API surface takes the same
credentials — a session or an `x-api-key` header:

| Surface | Path | Use |
|---|---|---|
| LLM index | `/llms.txt` | The short list of where to read next |
| Agent skill | `/skill.md`, `/skill` | Picks the one skill for the task in front of you |
| Skill family | `/skills/<package>/<skill>/SKILL.md` | The task walkthroughs |
| Docs | `/docs`, `/docs/book`, `/docs/adr` | The map, the manual, the ledger — as pages |
| Docs read API | `/api/docs`, `/api/docs/{slug}`, `/api/docs/nav` | The same corpus as JSON, with raw markdown |
| MCP | `POST /api/mcp` · `/.well-known/mcp.json` | Tools generated from the OpenAPI spec; the discovery descriptor |
| OpenAPI | `/api`, `/api/spec.json` | Scalar docs; the machine-readable spec |
| Typed RPC | `/api/rpc/{procedure}`, `/api/rpc/{plugin}/{procedure}` | Typed JSON-RPC |
| Deployed state | `/.well-known/version` | Fingerprint and per-remote digests |

## Reading the runtime's own state

When a document and the runtime disagree, believe the runtime. `.bos/` is its ledger
— local-only, regenerated by the command that owns it:

| Surface | Answers |
|---|---|
| `.bos/generated/runtime-map.json` | What composed, from where, and who owns each path |
| `.bos/bos.resolved-config.json` | What resolution produced — which remotes are local overrides |
| `.bos/logs/` | What actually ran — the truth of last resort |
| `.bos/deploy-state.json` | What was last published |
| `.bos/sync-backup/` | Copies of template-owned files a sync replaced |
| `bos.lock.json` (committed) | The frozen composition and the sync baseline |

## Status words

| Status | Meaning |
|---|---|
| Accepted | The decision is made; it may still be landing in phases |
| Proposed | The design is recorded but not committed |
| Superseded | Replaced by a later ADR, which it links; kept as history |
| Deferred | A plan parked deliberately, with the condition that re-enters it |
