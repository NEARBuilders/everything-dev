## Why this matters

This is the first real consumer of the grafting machinery: login and account
settings move out of the ui monolith into `plugins/auth/ui`, loaded via Module
Federation and grafted into the host's `_anon` and `_dashboard` mounts. It
proves the compose protocol end-to-end (SSR + client hydration + fallback)
with a high-value consumer, and it makes auth surfaces per-tenant overridable
via the existing `plugins.<id>.ui` config slot — the customization story the
platform sells. The failure-mode risk (unauthenticated login depends on a
remote) is mitigated by the #106 shared-dep identity guard (bad bundles are
refused before execution) and the CSR/SSR core-only fallbacks verified in
this plan.

## Steps

### Step 1: Scaffold `plugins/auth/ui`

Workspace with `package.json` (name `auth-ui` or `@citynode/auth-ui`; scripts
per the every-plugin/ui bundle convention — check `plugins/auth/package.json`
and the mf-build docs), `rsbuild.config.ts` using
`createUiSharedDeps` for the shared singleton list and emitting **both**
targets (client: `remoteEntry.js` + expose `./tree`; ssr:
`remoteEntry.server.js`). Directory:

```
plugins/auth/ui/
├── package.json
├── rsbuild.config.ts
└── src/
    ├── routes/
    │   ├── __root.tsx          # minimal root (no head chrome — host owns it)
    │   ├── _anon.tsx           # pathless mount declaration (id `_anon`)
    │   ├── _anon/login.tsx     # moved verbatim, imports adjusted
    │   ├── _dashboard.tsx      # pathless mount declaration
    │   └── _dashboard/settings/**  # moved verbatim
    ├── components/             # copied ui kit sources these routes import
    └── tree.ts                 # export default defineUiPlugin({ name: "auth", mounts: ["anon", "dashboard"], tree })
```

Route paths are preserved exactly (`/login`, `/settings/*`) — the graft
places them under the core tree, so URLs do not change. Imports of
`@/app` (`useApiClient`, `useAuthClient`, `sessionQueryOptions`) are replaced
by `everything-dev/ui/client` (+ the plugin's own contract for typed api
calls; the auth API key routes go through `authClient` only — verify per
route).

**Verify**: `bun run --cwd plugins/auth/ui build` → client + ssr artifacts
with both remote entries; `bun typecheck` → 0 errors.

### Step 2: Register in config + regenerate types

`bos.config.json`: `plugins.auth.ui = { development: "http://localhost:<port>",
... }` following the existing `plugins.<id>.ui` shape (see any local-ui plugin
entry in the resolved config; ports follow the planner's `plugins` ui port
allocation — pick the next free convention documented in
`packages/everything-dev/src/infra/types.ts` `CliPorts`). Run
`bos types gen` (or restart `bos dev`) to regenerate
`ui/src/lib/*-types.gen.ts` and plugin manifests.

**Verify**: `bos types gen` → exit 0; `bun dev` smoke → plugin ui loads, no
federation errors in `.bos/logs/`.

### Step 3: Delete the monolith routes

Remove `ui/src/routes/_layout/_anon/login.tsx`,
`ui/src/routes/_layout/_authenticated/_dashboard/settings/**` and
`settings.tsx`. Keep `_anon.tsx` and `_authenticated.tsx`/`_dashboard.tsx`
mount layouts in core (they define the mounts). Update any core nav/links
pointing at `/settings` (they keep working — path unchanged via graft).
Delete the moved tests from `ui/` and recreate/port them in
`plugins/auth/ui`.

**Verify**: `bun typecheck` → 0 errors; `bun run --cwd ui test` → pass.

### Step 4: Graft verification, both paths

With `BOS_UI_COMPOSE=1`:
- SSR: request `/login` unauthenticated → auth plugin tree composes → login
  HTML rendered; request `/settings` authenticated → settings rendered.
- Client: hydrate composes the plugin tree; full login → settings navigation
  works client-side (TanStack `<Link>` navigation, `waitUntil: "commit"` in
  browser tests per AGENTS.md).
- Fallbacks: block the plugin ui remote (kill its dev server) → SSR logs
  `[SSR] Compose plugin trees failed` and falls back to core-only; client
  falls back core-only without a hydration crash on non-auth pages.

**Verify**: `BOS_UI_COMPOSE=1 bun run dev` + manual curl of `/login` returns
the login form HTML; host test suite `host/tests/integration/ui-compose.test.ts`
extended with an auth-tree fixture grafting `_anon`/`_dashboard`.

## STOP conditions

- The auth plugin's backend (`plugins/auth/src`) needs changes to support the
  moved surfaces (it should not — authClient handles everything).
- Route paths collide with core routes after deletion (e.g. a core `/login`
  variant still exists) — report; do not re-path routes.
- The compose digest cache does not invalidate on `plugins.auth.ui` changes
  in dev (stale tree) — report; this is a pipeline bug, not a carve-out issue.
