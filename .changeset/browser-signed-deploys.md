One-trip deploys: `bos login` now installs everything `bos deploy` needs in a single browser approval — the scoped deploy key (`bundles:write`, account/gateway-scoped) as the session credential, and a registry-scoped delegate key added to your account by your wallet (kept in `.bos/session.json`, reused across re-logins). `bos deploy` then publishes through the gasless NEP-366 relay with no keychain and no env vars; any remaining browser approval happens before the build, never after. **Breaking:** `--wallet` is removed from `publish`, `deploy`, `rollback` and `promote` — a login session is the default path. Signing mode resolves explicitly: `--private-key`, then `publish.auth` (`key` / `session` / `custody`), then an available key (`NEAR_PRIVATE_KEY` / `~/.near-credentials`), then the login session; the preflight plan carries one validated `signing` arm. The login site now derives from the root of the `extends` chain (pass `--site` for a local stack), `--key` stays the explicit "also export a NEAR publish key / print the deploy key for CI" flag, and `cdn.upload` joins `cdn.origin` in the authored config so uploads no longer need `BOS_STORAGE_ORIGIN`. Custody publishes get a preflight gas-balance gate with the funding link, and the auth plugin mints deploy keys for the custody wallet's hex account. A failed deploy-key mint degrades to a plain session key with a warning.
