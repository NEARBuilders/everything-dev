New plugin: the Agent Connect control plane — every signed-in user gets an owner-controlled agent account on the NEAR Intents Agent API (https://api.agentsonintents.com). The owner signs the rules once with their wallet; agents hold revocable `ngt_` grant tokens that only act inside the owner-signed policy. The plugin consumes `@near-intents-agent-api/sdk` (catalog-pinned, the only protocol dependency — route outputs are the SDK's own types, never re-declared) and adds only platform concerns: session ownership via the auth context, the sealed grant-token vault (HKDF-SHA256 → AES-256-GCM, never sent to a browser), the pre-send intent ledger (persist before send; prepare routes accept an optional client idempotency key — same key replays the stored intent or resends the stored request, cross-type reuse conflicts), submit and status polling share one reconciliation path (a later success applies the same local effects as an immediate one), and the oRPC surface (`agent/create`, `agent/list`, `agent/{id}`, `agent/intents/prepare|submit|status`, `agent/{id}/grants`) which exposes the domain to REST and MCP through the host's OpenAPI mounts. Owner intents follow the BFF split — prepare returns `intent.payload` + preview, the browser signs via better-near-auth's `signAgentIntent`, submit carries the wallet's output. Dormant until `NEAR_INTENTS_AGENT_API_KEY` is configured; own `plugin_agent_connect` schema (`AGENT_CONNECT_DATABASE_URL`, pglite default); `AGENT_CONNECT_ENCRYPTION_KEY` isolates the vault key.
