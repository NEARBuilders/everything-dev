Call-only plugin entries (#848): a `plugins.<key>` attachment can now consume a deployed app's API as a typed oRPC client — `plugins.feedback.getProjectBySlug({ slug })` from any plugin's `createRouter`/Effect services — without federation-loading the remote bundle, composing its routes, or handing it secrets or a database. The entry is a regular plugin entry with two locators: `proxy` (the traffic endpoint — the live app origin whose `/api/rpc` serves; the attachment-level proxy field gains its runtime) and `contract` (a pure `bos://account/gateway[#target]` types locator whose targeted entry's stamped production — the artifact CDN — serves the sha256-verified contract types). The two origins differ in production, which is why one URL cannot play both roles. Detection is structural (proxy present, no `extends`/`path`/URL fields — declaring both fails loud), so there is no discriminator field. The host forwards `/api/rpc/{key}/*` to the proxy endpoint through the same dispatch seam as composed plugins with `x-api-key` server-side; typegen fetches types from the contract origin; readiness probes the endpoint's rpc ping (manifest-200/rpc-401 was false confidence); health surfaces the attachments as `plugins.rpc`; the runtime map marks them call-only.
