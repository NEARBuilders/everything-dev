`bos db repair --mode history-reset` no longer drops the migration journal wholesale and no longer re-applies into the wrong schema. Under the legacy shared journal (`drizzle.__drizzle_migrations`, the default storage before ADR 0045) the reset is now slug-scoped: it deletes only the rows whose hashes the workspace's local migrations reference, so resetting plugin A no longer wipes the recorded history of every sibling workspace and the api shell on the same database. Under per-workspace journals (ADR 0045) the drop is scoped to the workspace's own journal table by construction. The re-apply pass now runs the runtime migration runner (`runMigrations`) under the workspace's data schema (`plugin_<slug>` for plugins, `public` for api/auth) — the same journal, schema, search_path, and drift-tolerant preflight a boot performs — replacing the drizzle-kit pass whose config has no notion of the v2 data schema and which created `public`-schema copies of plugin tables without fixing the `drift-safe-repair` boot it was run for. A journal-only reset on a healthy consolidated database usually self-heals on next boot; the `public`-targeted drizzle-kit pass only added destruction risk. Fixes #664.
