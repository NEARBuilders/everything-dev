Per-identity PGlite data dirs — multiple in-process plugins no longer share one data dir (fixes #787). The zero-config default is now `pglite:.bos/db/<slug>` (slug = the workspace's migration slug, e.g. `pglite:.bos/db/api`, `pglite:.bos/db/auth`, `pglite:.bos/db/agent_connect`): multiple live PGlite instances on one data dir don't coordinate and silently corrupt committed data — heap/index divergence made `SELECT` see empty tables while `INSERT` failed with duplicate-key on empty tables (first SIWN sign-in broke). Changes: (1) `pgliteDefaultUrlForSlug(slug)` replaces the single shared default everywhere (`resolveDatabaseUrl`, bindings, conventional env templates, deploy smoke); `PGLITE_DEFAULT_URL` remains as the layout base/legacy-pin literal, `PGLITE_DEV_DATABASE_URL` is removed (use `pgliteDefaultUrlForSlug(normalizeDatabaseSlug(secret))`). (2) `createDatabaseDriver`'s pglite branch refuses a second concurrent open of one data dir in-process (decoded-absolute guard key — relative, `file://`, and bare spellings of one dir all collide), throwing with a remediation message; sequential close→reopen stays legal, in-memory stays exempt; `file://` URLs are now decoded before `mkdirSync` (the raw URL created a literal `file:` junk directory). (3) `bos dev`'s one-time repair splits `.env` pins that share the legacy `pglite:.bos/db` literal into per-identity subdirs (idempotent; only the exact legacy literal; a rewrite is skipped if its target dir is occupied by a pin that stays). (4) `bos dev` preflight fails any remaining composition where two or more `*_DATABASE_URL` secrets resolve to the same pglite dir (in-memory exempt). (5) The regression-env dev-data guard refuses any `pglite:.bos/db` URL including per-slug subdirs. Scaffolded plugin defaults, dev overlays, and templates pin per-identity dirs; ADR 0044 records the decision and supersedes ADR 0038's shared-dir topology. Real data sharing is unchanged on `postgres://` (plugin secrets fall back to `API_DATABASE_URL` with `plugin_<slug>` schema isolation).
