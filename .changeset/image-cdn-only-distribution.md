The universal image stages no dists and bakes no config — the CDN (`cdn.everything.dev`) is the single distribution source (ADR 0020/0021 amendment). The Dockerfile `runtime` stage drops the `dist-builder` COPY of `.bos/bundles` + `BOS_BUNDLE_DIR` and the build-time-resolved `bos.config.json` bare-start fallback, so `docker build --target runtime` skips the dist-builder stage entirely — exactly one build of the runtime's bytes exists anywhere (the deploy train's). This heals the SSR/browser pin divergence: the image's staged bytes and the CDN's uploaded bytes were not byte-identical (minifier variable allocation differs per build), so SSR rendered the image's hashed filenames while browsers fetched the published CDN pins → 404 → broken hydration. Boot is now identity-driven (`BOS_ACCOUNT`/`BOS_GATEWAY` → FastKV) or a mounted config (`--config-path`); a bare `bos start` with neither fails loudly. `bos mf check` falls back to the registry identity when no local authored config exists, keeping the in-image smoke gate green. `BOS_BUNDLE_CACHE_DIR` stays (the resilience artifact); `BOS_BUNDLE_DIR` remains an operator opt-in (mounted staged namespace) and the `regression` fixture target is unchanged. A universal image should boot from identity or a mounted config — never from image-build-time config state.
