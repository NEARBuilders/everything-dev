Framework-owned files: one inventory, honest markers, and same-version upgrades that leave them alone (ADR 0032). `bos upgrade` with no framework version change no longer runs the template sync — framework-owned files are only reconciled when the version actually changes (`bos sync` remains the explicit drift-pull). The ownership inventory moves to `services/scaffold/ownership.ts` (dropping the never-synced `tsconfig.contract.json` ghost), commentable owned files carry a canonical `FRAMEWORK-OWNED` header that says local edits are allowed and points at the upstream-issue protocol (https://github.com/NEARBuilders/everything-dev/issues), and the six files that kept lying "BE CAREFUL" headers after ADR 0023 (`ui/src/lib/api.ts`, `ui/src/lib/auth.ts`, `ui/src/routes/__root.tsx`, `ui/src/components/router-error.tsx`, plugin `ui/postcss.config.mjs`) are unmarked. Sync/upgrade output gains a shared outcome block, the upstream-issue protocol on conflicts, and an explicit "framework version unchanged" note; the init-upgrade skill's phantom `--force` flag is gone and the conflict table matches actual semantics (template applied, local backed up).
