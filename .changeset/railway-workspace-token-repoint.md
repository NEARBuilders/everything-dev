Children are tiered by Railway token scope; the pinned-child repoint becomes an opt-in advanced behavior. Railway authorizes CLI verbs by token scope: a project-scoped `RAILWAY_TOKEN` covers deploy commands (`redeploy`) but not the `serviceConnect` mutation behind `railway service source connect` — so every child deploy since rc.21 failed at the pin with "Unauthorized" *after* the config published (citynode.app, 2026-10-24, #598). The child railway leg now degrades cleanly by what the repo holds: a project token gets a plain `redeploy --from-source` — and when the platform pin resolves without the workspace token, the leg prints a drift notice (the service source follows the pin only under the token that can repoint it, so post-`bos upgrade` drift is loud, not silent); a workspace-scoped `RAILWAY_API_TOKEN` + `RAILWAY_PROJECT_ID` / `RAILWAY_ENVIRONMENT_ID` opts into the pin-following repoint+redeploy (the project token is dropped from the railway subshell, since the CLI prefers `RAILWAY_TOKEN` when both are set — including set-but-empty GitHub passthroughs). Omitting the token entirely stays publish-only (the leg soft-skips). A project-scoped child token is the default posture: workspace tokens mutate any project in the workspace, so they are never the default child credential. The root tier is unchanged — it never repoints and keeps the advanced image-setting train (image → digest handover → smoke → Railway pin). `consumer-deploy.yml` and `consumer-staging.yml` pass the workspace token and targeting vars through (staging with staging-specific overrides); the reusable composite action `.github/actions/install-playwright` carries the probe-gated browser install for child CIs (also adopted by the parent's own browser suites). Interim to #526/ADR 0035 — the reconciler dissolves the child leg and the per-child token entirely.
