The consumer Railway repoint accepts a workspace-scoped token. Railway authorizes the pinned child's `railway service source connect` (the `serviceConnect` mutation) only for workspace/account tokens — a project-scoped `RAILWAY_TOKEN` covers deploy commands (`redeploy`) alone, so every child deploy since rc.21 failed at the pin with "Unauthorized" *after* the config published (citynode.app, 2026-10-24). The railway leg now takes `RAILWAY_API_TOKEN` (workspace token, paired with `RAILWAY_PROJECT_ID` / `RAILWAY_ENVIRONMENT_ID` targeting vars) as the leg's token: when set it owns the whole leg and the project token is dropped, since the railway CLI prefers `RAILWAY_TOKEN` when both are set — including set-but-empty GitHub passthroughs. The root tier is unchanged (it never repoints). A failed repoint under a project token now appends the precise cause and remedy instead of the generic "check that your RAILWAY_TOKEN is valid" message. `consumer-deploy.yml` and `consumer-staging.yml` pass the workspace token and targeting vars through; the reusable composite action `.github/actions/install-playwright` carries the probe-gated browser install for child CIs (also adopted by the parent's own browser suites).
