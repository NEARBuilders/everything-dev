Deploy legs report structured outcomes and are runtime-tier aware: `bos deploy` exits 0 for consumer/child runtimes that publish successfully, instead of failing when the Railway leg cannot run. Each leg (image / smoke / railway) now carries `{ status: ok | skipped | failed, detail }` on the deploy result and the CLI renders a per-leg summary (✓ / – / ✗). A runtime that owns its image (`ci.image` configured or a Dockerfile at the config root) is "root" and keeps the hard gates — Railway requires a pinned digest. A runtime inheriting the universal image (ADR 0020/0021) is "child": the image and smoke legs soft-skip with a notice, and the Railway redeploy runs without a digest (`railway redeploy --from-source` is a reload trigger for the freshly published config; the token is project-scoped). "Config published, but the … leg(s) failed" names the failed legs. Child scaffolds declare `@opentelemetry/api` at the root so the `@better-auth/core` optional peer resolves — removing the recurring "Module not found" build warning in consumer CI; existing children receive it on their next `bos sync`.
