`bos import` now reconciles diverging migration chains instead of holding them back (NEARBuilders/everything-dev#393). Local journal entries already applied to the database are kept verbatim — never renumbered or rehashed — while colliding upstream migrations are renumbered and appended after the local tail: upstream's `0011_team-member-role` with a local tail at idx 12 becomes `0013_team-member-role` (`.sql` renamed, `meta/*_snapshot.json` renamed, `meta/_journal.json` rebuilt carrying upstream's `when`/`version`). Repeat imports converge: an upstream migration whose SQL content hash matches a locally imported one is recognized by content and not appended twice. The import report and console show the kept, appended (from→to), and content-matched sets plus what the next boot will apply versus what is already applied, and warn that renamed snapshots record upstream intermediate schema states (review `drizzle-kit generate` output against the merged chain). The chain is still held back only for unresolvable drift — content drift on an already-applied migration or an unreadable journal. Appended migrations gate the run behind `--yes`/interactive confirmation like conflicts; `ImportResult` gains a `migrationReconciliation` field (`kept`/`appended`/`contentMatched`) and `migrationCollisions` is now unresolvable-only (`tag-mismatch`).
